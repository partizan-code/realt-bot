# Repository Guidelines

## Структура проекта

`realt-bot` — асинхронный Python-бот, который собирает объявления об аренде квартир с Kufar и публикует их в Telegram-каналах шести городов Беларуси.

- `main.py`: конфигурация, парсинг через Playwright, история объявлений и отправка через aiogram.
- `logger_config.py`: настройка консольного логирования и файла `error.log`; сейчас файл ещё не отслеживается Git.
- `pyproject.toml`: версия Python и зависимости проекта.
- `.env.example`: перечень переменных окружения.
- `scripts/deploy.sh` и `realt-bot.service`: заготовки развёртывания на Linux.

Каталогов тестов и постоянных ресурсов пока нет. `img/`, файлы `ads_ids_<city>.json` и журнал ошибок создаются во время работы и исключены из Git.

## Команды разработки

Используйте Python 3.12+ и запускайте команды из корня репозитория:

- `uv sync` — подготовить окружение по `pyproject.toml`.
- `uv run python main.py` — запустить бота; команда может публиковать сообщения в настроенные каналы.
- `uv run python -m compileall main.py logger_config.py` — проверить синтаксис без запуска бота.

Зависимости `playwright`, `aiogram` и `python-dotenv` используются кодом, но пока отсутствуют в манифесте. До полноценного запуска объявите их и установите Chromium командой `uv run playwright install chromium`. Отдельного этапа сборки нет.

## Стиль и именование

Используйте четыре пробела, `snake_case` для функций, переменных и модулей, `UPPER_SNAKE_CASE` для констант. Сохраняйте асинхронную модель; избегайте блокирующих операций в цикле обработки городов. Для переносимых путей используйте `pathlib` или `os.path`. Форматтер и линтер пока не настроены.

## Проверка изменений

Автоматических тестов и порога покрытия пока нет. Для новых тестов используйте каталог `tests/`, имена `test_*.py` и стандартный `unittest`; запуск: `uv run python -m unittest discover -s tests -v`. Проверяйте извлечение полей, исключение повторных ID и ошибки отправки с подменой браузера и Telegram-клиента. Не используйте рабочие каналы в автоматических тестах.

## Коммиты и pull request

В истории есть один коммит: `init: структура проекта`; устоявшегося стандарта ещё нет. Пишите короткие сообщения с типом и смыслом изменения, например `docs: добавить руководство участника`. В pull request укажите цель, изменённое поведение, выполненные проверки и связанные задачи. При изменении селекторов приложите обезличенный пример объявления.

## Конфигурация и работа агента

Создайте `.env` по `.env.example`, заполните `TOKEN`, `ADMIN_ID` и городские `*_CH_ID`. Для запуска нужен локальный `re.kufar.by_cookies.json`. Не коммитьте токены, cookies, журналы и историю объявлений.

Перед работой проверяйте ветку, upstream и локальные изменения. При доступном upstream выполните fetch и безопасный fast-forward для чистого дерева. Сохраняйте чужие изменения; не применяйте force-push. Читайте и обновляйте `PROJECT_STATUS.md`, включайте его в коммит задачи. Общайтесь с владельцем по-русски.
