# Repository Guidelines

## Структура проекта

`realt-bot` — асинхронный Python-бот для публикации объявлений Kufar в Telegram-каналах шести городов Беларуси.

- `main.py`: конфигурация, парсинг через Playwright, история ID и отправка через aiogram.
- `logger_config.py`: консольное логирование и файл `error.log`.
- `browser_session.py`: состояние Chromium и пересоздание браузера после аварии.
- `pyproject.toml`, `uv.lock`, `.python-version`: зависимости, настройки Ruff и версия Python.
- `tests/`: тесты конфигурации; `.github/workflows/`: CI.
- `.env.example`: шаблон переменных окружения без секретов.
- `scripts/deploy.sh`, `realt-bot.service`: заготовки развёртывания на Linux.

`img/`, файлы `ads_ids_<city>.json` и журнал ошибок создаются при работе и исключены из Git.

## Команды разработки

Запускайте из корня репозитория:

- `uv sync --locked` — подготовить `.venv` по lock-файлу.
- `uv run --locked playwright install chromium` — установить браузер.
- `uv run --locked python main.py` — запустить бота; возможна публикация сообщений.
- `uv run --locked ruff check .` — проверить ошибки и порядок импортов.
- `uv run --locked ruff format --check .` — проверить форматирование.

Python 3.13 выбран в `.python-version`; минимум — 3.12. Добавляйте зависимости через `uv add`, инструменты разработки — через `uv add --dev`. Коммитьте манифест и lock-файл вместе. Отдельной сборки нет.

## Стиль и именование

Используйте четыре пробела, `snake_case` для функций, переменных и модулей, `UPPER_SNAKE_CASE` для констант. Сохраняйте асинхронную модель. Используйте переносимые пути через `pathlib` или `os.path`. Применяйте `uv run --locked ruff check --fix .` для импортов и `uv run --locked ruff format .` для форматирования.

## Тесты

Используйте стандартный `unittest`, каталог `tests/` и имена `test_*.py`. Запуск: `uv run --locked python -m unittest discover -s tests -v`. Перед запуском установите Chromium. Проверяются конфигурация, парсинг, подтверждение ID после доставки, резервный текст и восстановление браузера. HTML-примеры обезличены, браузерные тесты работают локально. Порог покрытия не задан. Для отправки используйте подмену Telegram-клиента. Не используйте рабочие каналы в тестах.

## Коммиты и pull request

В истории используются сообщения с типом, например `docs: заполнить README публичного проекта`. Пишите короткие сообщения, описывающие результат. В pull request укажите цель, изменённое поведение, проверки и связанные задачи. Для изменений селекторов прикладывайте обезличенный пример объявления.

## Конфигурация и работа агента

Создайте `.env` по `.env.example`, заполните `TOKEN`, `ADMIN_ID` и все городские `*_CH_ID`. Файл `re.kufar.by_cookies.json` необязателен. Не коммитьте секреты, сессии, журналы или историю объявлений.

Перед изменениями проверяйте Git и upstream, выполняйте fetch. Обновляйте чистую ветку только fast-forward. Сохраняйте чужие изменения; не используйте force-push. Читайте и обновляйте `PROJECT_STATUS.md`, включайте его в коммит задачи. Общайтесь с владельцем по-русски.
