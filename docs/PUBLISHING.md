# Параметры и формат публикаций

[К документации](README.md) · [Синтетический пример](../README.md#пример-публикации)

Источник правил — [listing.py](../listing.py) и настройки [config.py](../config.py). Ниже описан текущий шаблон; план новых форматов не меняет его автоматически.

## Извлечение и неизвестные значения

`parameters(ad, city)` работает с текстами карточки выдачи, без дополнительных запросов к объявлению. Исходные поля сохраняются в `ad`, нормализованные значения добавляются отдельно.

| Параметр | Правило |
| --- | --- |
| Комнаты, площадь, этаж | Из заголовка; положительные непротиворечивые значения. Для этажа проверяется `0 < этаж <= этажность`. Диапазоны и несколько несовпадающих значений остаются неизвестными. |
| Месячная цена | Положительный `Decimal` с явными BYN/рублями и месячным периодом: например, `1 200,50 р./мес.`. Пробелы и десятичная запятая нормализуются. |
| Район | Явная метка «район»/«р-н» или «Район:» и совпадение со словарём текущего города `DISTRICTS`. |
| Метро | Явная подпись `Метро:`; просто слова «рядом метро» недостаточно. |
| Условия аренды | Подписанные залог, комиссия, коммунальные платежи, срок и животные; дополнительно некоторые отдельные однозначные фразы. Несовпадающие утверждения не объединяются в подтверждённый факт. |

Примеры явных условий: `Залог: 500 BYN; Комиссия: нет; Коммунальные: отдельно; Срок аренды: 12 месяцев; Животные: нельзя`. Поддерживаются отдельные фразы «Без комиссии», «Без залога», «С животными можно/нельзя», «Без животных», а также предусмотренные варианты запрета после условия о детях.

Отсутствие условия не означает разрешение на животных или нулевые дополнительные платежи. `1000 р.`, `от 800 BYN/мес.`, диапазон, цена за сутки и USD не считаются подтверждённой месячной ценой BYN. Цена USD извлекается парсером, но текущим шаблоном не используется.

## Порядок блоков

`render_post()` формирует HTML для Telegram:

1. `✅` и жирные комнаты и площадь через ` · `; если оба неизвестны — «Квартира».
2. На следующей строке `💰` и жирная цена. При известной месячной цене — `1200 BYN/мес.`; иначе исходный текст цены или «цена за месяц не указана».
3. Через пустую строку расположение: жирный адрес, затем район/метро при наличии и если они ещё не содержатся в адресе, затем этаж. У района/метро префикс `📍`; перед адресом и этажом эмоджи нет.
4. Через пустую строку `🐈 Животные:` и жирное значение либо «не указано».
5. При наличии — `📌` и короткое описание курсивом.
6. `🔥` и жирная ссылка «Объявление на Kufar».
7. Через пустую строку `⌛ Размещено: ЧЧ:ММ`.
8. Через пустую строку жирная подпись со ссылками на шесть каналов из `SIGNATURE`.
9. В самом низу через пустую строку — хештеги, если есть известные значения.

Если комнаты, площадь или этаж не распознаны, исходный заголовок может быть добавлен в необязательные строки расположения. Неизвестные район, метро и этаж отдельными заглушками не выводятся.

Из нормализованных условий в посте показываются только животные. Распознанные подписанные фрагменты залога, комиссии, коммунальных платежей и срока, а также отдельные фразы «без залога»/«без комиссии» удаляются из описания. Это правила для заданных текстовых шаблонов, а не универсальное распознавание любого упоминания платежей.

## Исходные данные демонстрации

Пример в корневом README соответствует следующей синтетической карточке для `minsk`:

| Поле | Значение |
| --- | --- |
| `title` | `["2-комн. 54 м² 3/9 эт."]` |
| `price_byn` | `["1200 BYN/мес."]` |
| `address` | `["ул. Примерная, 10"]` |
| `description` | `["Район: Советский; Светлая квартира. Рядом парк."]` |
| `link` | `https://example.invalid/listings/1001` |
| `time` | `datetime.time(14, 30)` |

Описание не содержит условия о животных и метро: результат — «не указано» для животных и отсутствие строки метро. Подписанный район не повторяется в описании. В демонстрации форма шестиканальной подписи сохранена, её адреса условно заменены ссылками на `example.invalid`; действующая `config.SIGNATURE` в коде не менялась. Пример сверяется статически по правилам функции, без запуска публикации.

## Хештеги

Порядок — комнатность, цена, район; максимум три тега. Неизвестное значение не создаёт тег.

| Подтверждённая месячная цена BYN | Тег |
| --- | --- |
| Меньше 800 | `#до800BYN` |
| От 800 включительно до 1200 исключительно | `#800_1200BYN` |
| От 1200 включительно до 1800 исключительно | `#1200_1800BYN` |
| От 1800 включительно | `#от1800BYN` |

Другие примеры: `#комнат_2`, `#район_Советский`. Диапазоны задаются `PRICE_TAG_BANDS` и `PRICE_TAG_LAST`, районы — `DISTRICTS`. Нераспознанная цена может остаться текстом в посте, но не участвует в ценовых тегах.

## Выбор фотографии

`extract_ad()` берёт первый непустой `src`, нормализует относительный URL и принимает HTTP/HTTPS-ссылку, путь которой не оканчивается на `.svg`. Отсутствующий `src` обрабатывается без прежнего обращения к срезу `None`. Проверка MIME-типа, соответствия картинки объявлению и отдельная поддержка lazy-loading/`srcset` не реализованы; подходящий по URL ресурс может оказаться заглушкой.

Ошибка `failed to get HTTP URL content` сама по себе не доказывает отсутствие фотографии: пустое поле изображения ведёт сразу к тексту, а непустая ссылка на заглушку или недоступный ресурс — к попытке фото. Без ID карточки и URL изображения причину конкретного отказа нельзя восстановить по одному тексту ошибки.

Действующее поведение — текст при отсутствии фото и резервный текст после явного отказа Telegram. Старое решение baseline от 18 октября 2026 года об отложенном обходе ошибок фото описывало прежний код; текущая реализация уже содержит резервную отправку. Эта документация не изменяет политику публикаций автоматически.

## Экранирование, сокращение и доставка

Данные источника экранируются через `html.escape`. Ссылка должна иметь HTTP/HTTPS и непустой host. Длина оценивается консервативно в единицах UTF-16 после удаления HTML-тегов и разбора сущностей; бюджеты в конфигурации — 1024 для подписи и 4096 для текста.

Описание разбивается на фразы, повторы удаляются. Фразы добавляются целиком, пока соблюдаются бюджет поста и `POST_DESCRIPTION_LIMIT=500`. Условие длиннее `POST_CONDITION_LIMIT=120` заменяется на «подробности в объявлении». Необязательные строки расположения также добавляются только при наличии места.

Сначала строится обязательная часть с условием о животных, ссылкой, временем, подписью и тегами. Если она не помещается, `render_post()` возвращает `None`; повреждённый HTML обрезкой строк не создаётся.

При изображении и подходящей подписи отправляется фото. При отсутствии изображения или невозможности уместить подпись сразу отправляется текст. Если Telegram явно отклонил фото через `TelegramBadRequest`, выполняется резервная отправка полной текстовой версии без предпросмотра ссылки. При неопределённой сетевой ошибке резервный текст сразу не отправляется.

ID подтверждается после успешного фото или текста. Если не помещается даже обязательная часть текстового сообщения либо отправка завершается ошибкой, ID не подтверждается. Возможность повтора не является гарантией доставки: объявление может исчезнуть из выдачи, а неопределённый результат запроса может привести к дублю.

Экранирование защищает формат поста от HTML источника: похожий на тег текст должен отображаться буквально и не создавать чужие ссылки. Речь идёт о разметке Telegram, а не о выполнении JavaScript или серверного кода. Проверки граничных длин, эмодзи, сущностей и обязательной ссылки сохраняются при последующих изменениях шаблона.

Официальные справочники: [подпись `sendPhoto`](https://core.telegram.org/bots/api#sendphoto), [текст `sendMessage`](https://core.telegram.org/bots/api#sendmessage), [HTML-разметка Telegram](https://core.telegram.org/bots/api#html-style). Сверяйте ограничения с API и фактическими версиями библиотек, а поведение проекта — с кодом и изолированными проверками.
