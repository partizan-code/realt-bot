# Эксплуатация и диагностика

[К документации](README.md) · [Настройка](SETUP.md)

## Рабочий запуск

Приложение запускается из корня проекта командой `uv run --locked python main.py`, использует каналы из окружения и обновляет историю после доставки. Первый запуск выполняйте с тестовыми каналами после проверки конфигурации и прав.

Рабочий цикл, актуальные селекторы и реальную доставку после последних изменений ещё нужно подтвердить отдельно. Не запускайте несколько экземпляров с общей историей: блокировок и атомарной записи JSON нет. Файлы истории и сессии сохраняйте при обновлении кода; потеря истории может вызвать повторы.

## Логирование

[logger_config.py](../logger_config.py) настраивает Loguru:

- INFO и выше выводятся в stdout, ERROR и выше — в `error.log` в UTF-8.
- Общий минимальный уровень, уровни обработчиков и формат задаются в `config.py`.
- Формат использует поля Loguru `{time}`, `{level}`, `{message}`; сообщения приложения с данными используют f-строки.
- Повторный вызов `setup_logger()` удаляет прежние обработчики и не дублирует записи.
- `backtrace` и `diagnose` отключены, чтобы исключения не дополнялись дампом локальных значений.
- Ротация файла не настроена.

Рост журнала ограничивается только доступным диском. До согласованного внедрения ротации следите за размером файла и свободным местом; переполнение способно нарушить и запись истории. Срок хранения и ротацию по времени/размеру нужно выбирать отдельно, сохраняя нужные записи при изменении политики.

Ошибка отправки сейчас содержит канал и текст исключения, но не ID объявления или URL картинки; предупреждение о карточке также не идентифицирует её. Traceback явно не записывается этими обработчиками. Для дальнейшей диагностики нужны безопасный контекст города/ID/операции, результат запроса и счётчики отправок; токены, cookies и секретные параметры URL логировать нельзя. Предлагаемые изменения пока находятся в [плане](ROADMAP.md#надёжность-и-сопровождение).

В stdout есть число карточек, распознанных дат, сегодняшних, известных, ошибочных и новых объявлений. В файле ERROR обычный ход цикла не виден; нулевое число новых объявлений само по себе не доказывает ошибку или остановку процесса. По одним ошибкам без числа попыток/успехов нельзя вычислить долю отказов.

Исторический разбор фрагмента за 17–18 октября 2026 года отмечал 17 отказов загрузки фото в четырёх каналах и два таймаута ожидания `load`. Это числа только того фрагмента, а не всего периода работы. Отсутствие ID и URL не позволило установить ресурс и причину отказа; медленные сторонние ресурсы, нехватка памяти и отсутствие фото оставались предположениями. Эти сведения не являются результатом новой проверки журнала.

## Проверка разметки Kufar

Если страницы загружаются, но результаты отсутствуют, сначала сопоставьте счётчики цикла. Нулевые новые объявления могут означать известные ID, отсутствие сегодняшних карточек либо проблему полей.

Для отдельно разрешённой сетевой диагностики при доступном Kufar:

```bash
uv run --locked python scripts/inspect_kufar.py --city minsk
```

Значения `--city`: `minsk`, `gomel`, `mogilev`, `vitebsk`, `grodno`, `brest`; по умолчанию `minsk`. Скрипт открывает публичную выдачу через Chromium. Он не вызывает `config.configure()`, не читает `.env`, не использует рабочий файл cookies, не меняет историю и не отправляет Telegram-сообщения.

Результат — `tmp/kufar-diagnostic/<city>.json`, HTML и PNG рядом. JSON содержит HTTP-статус, URL, признаки DOM и количество совпадений **старых** селекторов из `LEGACY_AD_SELECTORS`. Нули по старым селекторам сами по себе не означают неисправность текущих `CARD_SELECTOR` и `AD_SELECTORS`: сравните сохранённую разметку с действующей конфигурацией.

Автоматическая отправка скриншота администратору в текущем основном цикле отсутствует; `ADMIN_ID` всё ещё обязателен для конфигурации. Если такая диагностика понадобится, отдельно определите ветки таймаута/пустой выдачи и обработку сбоя самой диагностики. Для загрузки локального файла aiogram требуется обёртка вроде `FSInputFile`, а не строка локального пути: [aiogram](https://docs.aiogram.dev/en/latest/api/upload_file.html), [Telegram: отправка файлов](https://core.telegram.org/bots/api#sending-files). Реальная отправка файла в рамках документации не проверялась.

Каталог исключён из Git. Перед передачей отчёта обезличьте HTML, текст и снимки; не публикуйте данные пользователей. Проверьте доступность сайта и влияние VPN/сети в своём окружении. В рамках переработки документации диагностика не запускалась.

## Восстановление после ошибок

Crash, закрытие страницы и отключение Chromium обрабатываются через `BrowserSession` с одной повторной попыткой города. HTTP-ошибка, таймаут или отсутствие карточек не означают, что исправный браузер нужно автоматически пересоздать. Подробные интервалы — в [ARCHITECTURE.md](ARCHITECTURE.md).

Явный отказ фото может переключить публикацию на текст. При неопределённой сетевой ошибке доставка не подтверждается; перед ручной повторной отправкой учитывайте, что первый запрос мог быть принят Telegram. Исчезновение объявления из выдачи не является доказательством сдачи квартиры.

## Сохранение и восстановление истории

Сохраните последнюю пригодную копию истории до отдельно согласованных восстановлений и миграций. Не удаляйте повреждённый JSON ради получения пустой истории и не считайте отсутствие файла обычным первым запуском без проверки обстоятельств: это может привести к повторным публикациям. Восстановление затрагивает пользовательские данные и требует выбранного источника, резервной копии и согласования.

Старые версии добавляли ID до ответа Telegram. Поэтому наличие ID в таком файле, включая 50 уникальных строк на город, не подтверждает доставку каждого объявления. При переносе данных различайте наблюдение, попытку отправки и подтверждённую доставку; не восстанавливайте статусы только по числу записей.

Для отката сохраняйте исходную рабочую версию, историю и сессию. Не переписывайте существующие production-коммиты и теги при исправлениях. Сбой очистки ресурсов не должен скрывать исходную ошибку запуска; целевое поведение exit status и перезапуска процессным менеджером нужно отдельно согласовать и проверить, включая неверный storage state и отказ создания страницы.

## Linux-деплой

[scripts/deploy.sh](../scripts/deploy.sh) и `realt-bot.service` — заготовки, а не подтверждённое автоматическое развёртывание:

- Скрипт вызывает `git pull origin main` без `--ff-only` и проверки чистоты дерева; не запускайте его автоматически без отдельной адаптации.
- Далее выполняется `uv sync --locked --no-dev`; установка Chromium и проверка успешного запуска не включены.
- Команда перезапуска сервиса закомментирована.
- Unit содержит пользователя и абсолютные пути конкретного сервера; `ExecStart` использует uv.
- Workflow GitHub Actions выполняет проверки и не развёртывает приложение.

Перед использованием отдельно согласуйте серверный Python/venv или uv, пути, пользователя, browser dependencies, секреты и способ запуска. Проверьте права публикации, единственный экземпляр процесса, сохранность истории и план отката. Эти действия не выполнялись при обновлении документации.

## Секреты и локальные файлы

В Git не должны попадать `.env`, браузерная сессия, `.venv/`, журналы, история ID, локальные базы и диагностические материалы. Наличие файла в `.gitignore` не прекращает его прежнее отслеживание автоматически.

Не выводите токены и cookies в ошибки, issues и PR. При утечке токена отзовите и замените его. Отсутствие совпадений при ограниченном поиске токенов или заголовков ключей не гарантирует отсутствие всех секретов; состав публикуемых файлов проверяется отдельно. Текущее хранение JSON-истории и отсутствие архива ограничивают восстановление данных; резервное копирование локальных файлов организуется отдельно.
