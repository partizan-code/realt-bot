# Проверки и CI

[К документации](README.md)

## Команды

Из корня проекта после установки зависимостей и Chromium:

```bash
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked python -m unittest discover -s tests -v
```

В проекте используется стандартный `unittest`; порог покрытия не задан. Подготовка окружения описана в [SETUP.md](SETUP.md). Для разрешённых правок кода доступны `uv run --locked ruff check --fix .` и `uv run --locked ruff format .`; они изменяют файлы и не являются командами проверки без правок.

Зависимости добавляются через `uv add` или `uv add --dev` с совместным сохранением манифеста и lock-файла. Для проверки документации установка зависимостей не требуется.

## Что проверяют существующие тесты

| Файл | Область |
| --- | --- |
| [test_config.py](../tests/test_config.py) | Явная загрузка окружения, обязательные поля и числовые ID, ошибки без раскрытия значений |
| [test_parsing.py](../tests/test_parsing.py) | Извлечение карточек из локального HTML, разделители параметров, варианты разметки, сегодняшние/известные/повторные ID, ошибки полей |
| [test_listing.py](../tests/test_listing.py) | Нормализация и неизвестные значения, условия о животных, границы тегов, порядок блоков, экранирование, сокращение и лимиты |
| [test_delivery.py](../tests/test_delivery.py) | Подтверждение истории только после успеха, частичная доставка, резервный текст, подпись и неопределённая сетевая ошибка |
| [test_browser_recovery.py](../tests/test_browser_recovery.py) | Закрытие страницы, отключение Chromium, crash, повтор города и ограничение числа попыток |
| [test_logging.py](../tests/test_logging.py) | Уровни обработчиков, отсутствие дублей, общий минимум и отключение дампа локальных переменных |

Браузерные тесты используют локальный HTML через `page.set_content()`; навигация при проверке парсера подменяется. Telegram заменяется mock-клиентом, история и файл логов направляются во временные каталоги, загрузка `.env` в тестах конфигурации подменяется.

Эти проверки не подтверждают совместимость с текущим сайтом, реальную доставку или права бота в каналах. Изолированные проверки нельзя использовать как основание для заявления о production-готовности.

## Сценарии для последующих изменений

Ниже сохранены критерии из исторического анализа baseline `648922d` от 18 октября 2026 года с учётом текущего кода. Часть уже покрыта перечисленными тестами; таблица задаёт, что сохранить и чем дополнить проверки при соответствующей задаче, а не утверждает наличие или успешность каждого сценария сейчас.

| Область | Проверяемый результат |
| --- | --- |
| Подтверждение доставки | Первая ошибка не записывает ID; последующий успех записывает его; частичный успех и прерванная пачка сохраняют уже доставленные ID; известный ID пропускается. |
| Фото и резервный текст | Отсутствующий `src`, несколько изображений, заглушки, URL JPEG с параметрами и другие форматы соответствуют выбранной политике; явный отказ фото допускает текст, неопределённая сетевая ошибка не создаёт немедленную вторую отправку. |
| HTML и лимиты | `<`, `>`, `&`, кавычки и похожий на тег текст остаются буквальным содержимым; разметка бота и ссылка сохраняются. Граничные длины подписи/текста, эмодзи и сущности считаются без повреждения HTML. |
| История при ошибке записи | На временном хранилище прерывание/ошибка записи не уничтожает последнюю пригодную историю; успешная замена целостна. Проверять вместе с координацией процессов. |
| Схема и восстановление истории | Различаются отсутствие, пустой файл, невалидный JSON, объект вместо массива, нестроковые и повторные ID; возврат ID после вытеснения подчиняется согласованной политике. |
| Параллельность и полнота | Два изолированных обработчика не публикуют один ID одновременно; набор более 30 карточек, длительный простой и переход через полночь соответствуют выбранным требованиям. |
| Готовность и поля | Задержанная загрузка, меняющийся список, посторонние контейнеры, пустая выдача и изменённые селекторы различаются. Некорректные дата/время/href не создают неверных ID; пустые необязательные поля не дают `None` в тексте. |
| Запуск и восстановление | Отказ на этапах launch/context/page, недоступный браузер и неподходящий storage state дают ограниченные повторы и очистку; сбой очистки не скрывает исходную ошибку; итоговое завершение соответствует политике менеджера процессов. |
| Диагностика и логи | По искусственному отказу видны город/ID/операция без секретов. Если согласована отправка снимков, локальный InputFile и ошибка самой диагностики проверяются с mock Bot; ротация — на временных логах. |
| Конфигурация и окружение | Ошибки настроек не раскрывают значения, импорт не запускает внешние действия, иной CWD не меняет незаметно хранилище; исходная сессия сохраняется, отдельное окружение воспроизводимо. |
| Ресурсы и стоимость операций | Повторная настройка логгера не дублирует вывод; при согласованном переиспользовании Bot сессия закрывается после успеха и ошибки. Ожидание cookies не маскирует другие ошибки; моделируемый медленный диск не блокирует цикл сверх выбранного бюджета. |

В исходном анализе выбранные функции baseline проверялись через AST с подменами, а не с реальными интеграциями. Эти исторические результаты не доказывают работу текущих версий библиотек, production-файлов, Kufar или Telegram. Производительность и конкретные уязвимости тогда не были установлены. Подтверждение устранения риска требует ссылки на фактическое изменение и описания выполненной проверки.

## GitHub Actions

[Workflow Checks](../.github/workflows/checks.yml) запускается на `push` и `pull_request` с правом `contents: read`.

| Параметр | Значения |
| --- | --- |
| ОС | `ubuntu-latest`, `windows-latest` |
| Python | `3.12`, `3.13` |
| Подготовка | `uv sync --locked` |
| Статические проверки | Ruff check и format check |
| Chromium | `playwright install --with-deps chromium --only-shell` через uv |
| Тесты | `python -m unittest discover -s tests -v` через uv |

Матрица содержит четыре сочетания ОС и Python. macOS в ней нет. Конфигурация workflow подтверждает состав проверок, но не успешный результат запуска; результаты нужно смотреть для конкретного коммита в GitHub Actions. Бейдж CI в README не добавлен.

## Изменения документации

Для правок только Markdown проверяйте структуру заголовков, закрытие блоков кода, относительные ссылки, соответствие команд исходникам и конфигурации, синтетичность примеров и diff. Не запускайте рабочий бот, сетевую диагностику и функциональные тесты ради таких правок.

При переработке этой документации выполнены статические проверки; функциональные тесты, CI, обращения к Kufar и Telegram не запускались. Исторические результаты в [PROJECT_STATUS.md](PROJECT_STATUS.md) не являются результатами текущей сессии.
